# ADR 0003 · 知识层与经验层分表、分检索、分注入

- 状态：已采纳
- 日期：2026-11

## 背景

知识是事实性、相对稳定的内容；经验是过程性、情境相关的内容，需要按相似情境召回并验证效果。

## 决策

- 知识：`memory_event`，kind 为 fact / preference / decision 等，进 boot 主动注入。
- 经验：`experience_event`，字段包含 situation / action / outcome / lesson / conditions / tags / confidence，不进 boot，按情境检索或当轮注入。
- 经验有独立反馈表与置信度淘汰；知识用生命周期与衰减。
- 两者共享 project/visibility 语义与版本链模式，但不共享表。

## 放弃的方案

- **只用 kind 区分**：检索、注入、反馈、生命周期都不同，混表会让查询与维护逻辑互相污染。
- **经验直接复用知识表**：无法表达情境、做法、结果和反馈闭环。

## 后果

- 两套存储与测试，代码量增加。
- 反思需要双输出，并分别做去重。
- 迁移与导出分别处理；经验新增 JSONL 导出。

## 重审条件

如果经验最终只需要“带标签的知识”，可以合并；目前反馈闭环与情境检索不支持这一简化。
