# ADR 0002 · 单用户阶段用 SQLite 单写者

- 状态：已采纳
- 日期：2026-11

## 背景

单用户、低并发、单进程；未来可能多用户或更高写入量。

## 决策

- 主存储用 SQLite（`node:sqlite`），开启 WAL 与 `busy_timeout = 5000`。
- 领域层只暴露 `MemoryStore` / `ExperienceStore` / `EpisodeStore` 接口；插件不直接 import `node:sqlite`（依赖守卫强制）。
- 表结构保留 `project_id` / `visibility` 等低成本兼容字段。
- 文件（JSONL）只做导出、备份、快照，不做运行时主存储。
- 不引入分片、复杂乐观锁、消息队列。

## 放弃的方案

- **用 JSON 文件做主存储**：并发写、事务、崩溃一致性、查询都要自己实现。
- **单用户直接上高并发 schema**：多租户/分片/重试在单用户下几乎不触发，维护成本持续存在。

## 后果

- 写是串行的；多个插件共用连接时靠 WAL + busy_timeout 排队。
- 容量边界明确：单进程、单写者、低并发。
- 未来换 Postgres 时新增适配器，不改插件逻辑与 domain 算法。

## 重审条件

多用户并发写、写入吞吐持续接近瓶颈、需要跨进程共享。
